# 《弦刃 Resonant》设计实现说明

本文件解释 Demo 如何把 GDD 的「打击感 ＞ 战斗可玩性 ＞ 音乐完整性」翻译成可运行的
系统。所有时间单位为秒，BPM 为 120（一拍 0.5s，一小节 2.0s，32 小节 = 64s）。

---

## 1. 核心循环的落地

```
探索（横向移动/平台）
  → 观察敌人前摇
  → 选择四种攻击之一
  → 闪避/跳跃规避
  → 命中帧结算节奏
  → 连击/音效/特效反馈
  → 清场
  → 共鸣封印（节拍 + 指定攻击）
  → 下一声部归位
  → Boss 三阶段
  → 终章四击
  → 完美或普通结算
```

没有任何独立音游界面，没有需要玩家手动点击的乐器。音乐评价完全寄生在战斗动作上。

### 1.1 首次游玩教学

首次点「开始演奏」会进入内嵌在真实关卡里的六步互动教学（`tutorial_overlay.gd`）：

1. `A/D` 移动到练习木桩；
2. `W` 跳跃；
3. `K` 命中木桩；
4. 在拍点上完成一次 GOOD 以上命中；
5. `J/L/I` 三种攻击各命中一次；
6. `Shift` 闪避。

教学期间普通敌人隐藏、木桩不带攻击性；木桩使用真实的 `receive_attack` 和
`Conductor.judge()`，所以教程推进是真实动作的结果。完成后木桩消失、教学门打开、
敌人恢复。菜单「玩法教学」可随时重玩；`Enter` 可跳过，`Settings.tutorial_seen`
记录是否看过。教学视频见 `docs/resonant_tutorial.avi`。

## 2. 玩家状态机

角色原点在脚底，`CharacterBody2D` 胶囊 16×72，世界地面线 `y=610`。

```
Idle ⇄ Run ⇄ Jump / Fall
  ↓
LightAttack / HeavyAttack / Thrust / Launcher
  ↓ (startup → active → hitstop → recovery)
Idle / Fall
  ↓
Dodge (i-frames)   Hit   Death
```

### 2.1 移动参数

跳跃键为 **W**；菜单中的 `↑/↓` 也使用 W/S，但两者不会同时生效（只在对应场景处理）。

| 参数 | 值 |
|---|---:|
| 跑速 | 350 px/s |
| 地面加速度 / 摩擦 | 3000 / 3400 |
| 空中加速度 | 2200 |
| 重力 / 最大下落 | 2250 / 1250 |
| 跳跃初速 | −785 |
| 土狼时间 / 跳跃缓冲 | 0.10 / 0.13 |
| 闪避速度 / 时长 | 790 / 0.18 |
| 闪避无敌 / 冷却 | 0.26 / 0.34 |
| 受击无敌 | 0.72 |
| 空中闪避次数 | 1 |

跳跃高度约 131 px，足以跳上 490–540 高度的平台，但不足以跳过 300px 高的门。

### 2.2 四种攻击

| id | 键 | 前摇 | 有效 | 后摇 | 伤害 | 打击停顿 | 备注 |
|---|---|---:|---:|---:|---:|---:|---|
| light | K | 0.06 | 0.10 | 0.15 | 10/11/15 | 0.045 | 三连；第 3 段更高伤害 |
| heavy | J | 0.27 | 0.12 | 0.46 | 30 | 0.13 | 破甲、强击退、震屏 8 |
| thrust | L | 0.105 | 0.12 | 0.27 | 16 | 0.05 | 突进 840 px/s，长距离 |
| launcher | I | 0.155 | 0.13 | 0.335 | 14 | 0.065 | 垂直击飞 −730 |

所有攻击都有显式的 `startup → active → recovery`，命中检测只在 active 窗口轮询。
攻击前摇/后摇是刻意设计的：玩家必须**预判**拍点，而不是看到拍点再按。

### 2.3 取消规则

- 轻攻击可在有效帧后半段被下一段轻攻击取消。
- 闪避可以在后摇 18% 之后取消攻击，但不能取消前摇/有效帧。
- 所有攻击输入有 0.16s 缓冲，跳跃有 0.13s 缓冲。
- 受击会中断攻击和连击，但没有长到令人沮丧的倒地时间。

## 3. 节奏判定

### 3.1 判定来源

每次攻击命中调用 `Conductor.judge()`：

```
song_time = playback_position + time_since_last_mix − output_latency
judge_time = song_time + settings.offset_ms/1000
delta = judge_time − nearest_beat
```

判定使用**有符号偏差的绝对值**，显示时保留正负号帮助玩家调整。

| 偏差 | 等级 |
|---|---|
| ≤ 50ms | PERFECT |
| ≤ 100ms | GREAT |
| ≤ 180ms | GOOD |
| > 180ms | 普通 |

### 3.2 为什么不是按键帧

轻攻击 60ms 前摇、重击 270ms 前摇，如果按“按键时间”判定，重击在拍点按下几乎必然
在拍点后 0.27s 才命中。因此 Demo 统一以**命中帧**为准，并在教学提示与 HUD 节拍灯中
提示“提前出手”。这是本作与普通音游最大的操作差异。

### 3.3 音频延迟

- 自动减去 `AudioServer.get_output_latency()`；
- 玩家手动校准会再写一个 `offset_ms`（±200ms）；
- 暂停时冻结 stream，恢复时从原位置继续；
- Boss 换曲时重新建立时间轴，与场景边界对齐。

## 4. 连击与准确度

- 每次有效命中 `combo += 1`，同帧命中多个目标会分别计数。
- 普通命中（>180ms）**不会**断连击，但权重只有 0.08。
- 落空不立即断连击，只让连击计时器提前 0.7s 冷却。
- 受击立即 `combo = 0`，伴随红色闪屏、受击音效与镜头震动。
- 闪避成功单独计数，并在玩家头顶显示 `DODGE`。
- 连击 4 秒没有新命中自然消失。

准确度：

```
accuracy = (PERFECT + 0.78·GREAT + 0.5·GOOD + 0.08·普通) / 总命中
```

结算显示为百分比；它不直接决定音乐层，但参与完美乐章判定。

## 5. 音乐系统

### 5.1 素材

`tools/gen_audio.py` 用 numpy 合成 7 条 32 小节（64.0s）单声道 32kHz WAV：

| stem | 内容 |
|---|---|
| `level_pulse` | 轻鼓点、rim、shaker、bar 起点心跳 |
| `level_bass` | kick/snare/hat + Am–F–C–G 贝斯 ostinato |
| `level_melody` | 8 小节旋律、延迟、四轮变奏 |
| `level_harmony` | 和声 pad、钟琴琶音、弦乐 |
| `boss_pulse` | 低音鼓、工业 tick、drone |
| `boss_lead` | 16 分 ostinato、铜管刺、弦乐主题 |
| `boss_coda` | 合唱、定音鼓、胜利号角；终章叠加 |

全部使用同一个采样零点和 120 BPM 网格。Godot 侧每个 stem 一个
`AudioStreamPlayer`，设置 `LOOP_FORWARD`，开始时同帧 `play(0.0)`。

### 5.2 动态层

- 初始仅 `pulse` 可听；其它 stem 以 −70dB 静音播放，保持采样同步。
- 清场 + 共鸣封印完成后，`GameState.unlock_layer(i)`；`Conductor` 监听事件，
  记录 pending layer。
- `_process()` 检测小节号变化，到下一小节才把对应 stem 淡入。
- 淡入音量：`[-12, -9, -10, -14] dB`（低音最大，和声最轻）。
- Boss 换曲：停止 level stem，启动三条 boss stem。
- 终章 4/4：`boss_coda` 在下一小节从 −70dB 淡入；低音/lead 再调整音量。
- 总输出过一个 Master limiter，防止层叠 + SFX 时硬削波。

### 5.3 音效

- `swing_*` 在攻击开始时播放（破风）。
- `hit_*` 在命中帧播放（冲击）。
- `perfect / great` 作为节奏奖励叠层，不影响命中音的即时性。
- 敌人死亡、破甲、封印、Boss 攻击、终章均有独立音效。
- 22 个 `AudioStreamPlayer` 组成 SFX 池；每次播放独立 pitch 抖动。
- BGM 与 SFX 分离：即使完全脱拍，命中音效也立刻响。

### 5.4 暂停与恢复

- `Main` 暂停时设置 `get_tree().paused = true`；
- `Conductor.set_paused(true)` 对所有 stem 设置 `stream_paused = true`；
- `get_song_time()` 在暂停期间返回冻结位置；
- 继续时恢复 stream，并把 `_current_bar` 置 -1，使 pending 层在正确小节应用。

## 7. 敌人

### 7.1 共性

`CharacterBody2D`，配置驱动，四型共享：

- 距离激活（760px）；
- `Idle → Approach → Windup → Attack → Recover`；
- 前摇有地面圈/弧线预警；
- 命中判定使用实际距离/矩形，不依赖动画事件；
- 受击：闪白、击退、hit-stop、poise 削减；
- poise 归零进入 stagger，随后恢复；
- 死亡：专属音效、音符碎片、世界计数。

### 7.2 差异

**音符兽**：HP 30，速度 148，攻击距离 62，前摇 0.36；攻击是向前的短扑。

**重拍守卫**：HP 112，速度 74。正面护甲会完全格挡轻击/突刺/挑空，并发出金属声；
`J` 低音重击会破甲并造成 1.55s 硬直，破甲后 5s 恢复。攻击是震地 AOE。

**高音精灵**：HP 38，悬浮在玩家上方约 126px，保持距离并发射可被斩掉的音符弹。
近战需要跳跃/突刺/挑空。

**失谐者**：HP 76，速度 186。每次攻击前摇随机乘 0.68–1.32，且冷却随机；
它有意不服从固定节拍，迫使玩家看动作。

### 7.3 投射物

`note_projectile.gd`：速度 340，重力 50，生命 4s，可被玩家攻击斩掉；
进入“hurtable”组，`count_rhythm = false`，所以切弹不会污染节奏统计。

## 8. Boss：失序指挥家

Boss 原点在脚底，独立 `Node2D`，不是放大敌人。

### 8.1 时间轴

- 每招开始于拍点；前摇结束在下一个（或 1.5 个）拍点，然后立即结算。
- 攻击后进入 recovery，再回到 idle；idle 的下一招对齐到拍点。
- Phase 1：固定 1 拍前摇；招式池 slam / sweep / arpeggio。
- Phase 2：42% 概率 1.5 拍前摇；recovery 缩到 0.5 拍；slam 55% 概率接半拍后的 sweep。
- Phase 3：前摇 0.75 或 1 拍；每两次攻击后核心暴露 4 拍。

### 8.2 招式

- **slam**：地面冲击波，仅对地玩家命中；跳跃或闪避可躲。
- **sweep**：前方 330px 弧形横扫，高伤害，需要闪避穿过或拉开。
- **arpeggio**：5 枚音符弹从上方落下，可切，形成空中/横向压力。

### 8.3 核心

- Phase 3 身体完全无敌；命中显示金属火花但不造成伤害。
- 核心暴露 4 拍，`get_hurtbox()` 变为核心矩形。
- 核心伤害 ×1.35；命中会推进 HP。
- 每两次攻击后再次暴露，节奏为“攻击—攻击—核心窗口”。

### 8.4 终章演奏

HP 归零 → `state = Finale`，核心常驻；从下一个小节开始，四个提示位于
`start + 0/2/4/6` 拍：

| 提示 | 攻击 | 键 |
|---|---|---|
| BEAT 1 | 快速斩击 | K |
| BEAT 2 | 音波突刺 | L |
| BEAT 3 | 挑空攻击 | I |
| BEAT 4 | 低音重击 | J |

**为什么是每 2 拍而不是连续 4 拍**：低音重击总时长 0.85s、挑空 0.62s，
在 0.5s 间隔内要求连续命中会让“击中拍点”变成不可完成的操作。Demo 选择每击间隔
1.0s，但每一击仍然必须命中在拍点 ±205ms 内；这保留了“安排前摇、提前出手”的核心，
同时让四击可以被正常玩家完成。这个取舍是可调参数，不是隐藏机制。

- 命中窗口内 + 正确音色 → 成功，金色反馈，`finale_hits++`。
- 窗口内 + 错误攻击 → 该击失败，提示所需攻击。
- 过早/过晚 → 不消耗提示，但会被格挡，不给伤害。
- 4/4 → coda、全轨、金色终章演出、S 级前置条件。
- 少于 4 → 仍然击败 Boss，进入 A/B 级结算，音乐保持不完整。

## 9. UI / 结算

- 顶部左：区域、目标、副目标、临时教学提示。
- 顶部中：四声部条与关键音符 pips；Boss 战时下方显示 Boss 血条与阶段点。
- 顶部右：CHAIN 数字、准确度、最大连击。
- 底部左：生命。
- 底部中：四拍节拍灯（当前拍扩张）。
- 底部右：K/J/L/I 攻击提示；终章时高亮当前所需攻击。
- 中央：PERFECT/GREAT/GOOD/普通 与 ±ms。
- 终章：顶部四张提示卡，显示成功/失败、下一拍倒计时。
- 暂停：继续/音频校准/重新开始/返回标题，显示声部/准确度/最大连击。
- 结算：等级、乐章完整度、准确度、PERFECT/GREAT、受击/死亡、关键音符、
  四击结果、用时；S 级有金色射线与 `PERFECT PERFORMANCE`。

### 完美条件

结算的「乐章完整度」把四个声部与终章 coda 合计为 5 个单位：
`(声部数 + 成功终章 ? 1 : 0) / 5`。因此 Boss 胜利但终章失败时显示 80%，
完美演奏才是 100%。

`GameState.is_perfect()`：

```
boss_defeated
&& all 4 layers
&& key_notes >= 4
&& finale_hits == 4 && finale_success
&& accuracy >= 0.68
&& max_combo >= 12
&& all four attacks used
```

评级：

- S 完美乐章
- A 重奏者（Boss 胜、准确度 ≥72%、至少 3 声部）
- B 归位（Boss 胜但音乐/演奏不完整）
- C 中断的乐句（未击败 Boss；Demo 中因自动复活，通常只在异常退出时出现）

## 11. 已知设计取舍

1. **Boss 终章每 2 拍一击**：见 8.4；可改为 1 拍，但需要缩短重击/挑空后摇。
2. **死亡复活而非 Game Over**：让 3–5 分钟的 Demo 不因一次失误重来；
   代价是难度偏低，死亡只影响结算与连击。
3. **固定 32 小节循环**：便于保持 stem 采样锁相；长关卡会重复。
4. **封印失败可重试**：不设置永久失败，避免卡关；声部解锁仍需节奏。
5. **无存档成长**：GDD 的 P2，未加入。
6. **纯程序美术**：没有外部素材依赖；代价是角色/敌人细节靠形状与动效。
7. **Boss 换曲是硬切**：场景切换语义明确；若要无缝，可在 level 尾帧做交叉淡化。
